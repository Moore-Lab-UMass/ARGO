# Data and queries

All data comes from the ENCODE SCREEN GraphQL API (`https://screen.api.wenglab.org/graphql`), through the proxy at `/api/graphql`. Every query is defined in [src/lib/graphql/queries.ts](../src/lib/graphql/queries.ts).

## Which query feeds what

| Query constant | Used in | Purpose |
| --- | --- | --- |
| `REF_CHECK_QUERY` | ArgoUpload | Check reference alleles against the genome |
| `SNP_QUERY` | SnpUpload | rsID → coordinates and alleles |
| `BED_INTERSECT_QUERY` | useIntersectingCcres | cCREs overlapping the regions (GRCh38) |
| `ALLELE_QUERY` | useSequenceRows | Conservation values from a bigWig track |
| `MOTIF_RANKING_QUERY` | useSequenceRows | Motif ref/alt scores per region |
| `MAX_Z_SCORES_QUERY` | useElementRows | cCRE class and max z-scores |
| `BIOSAMPLE_Z_SCORES_QUERY` | useElementRows | Z-scores in a selected biosample |
| `ORTHOLOG_QUERY` | useElementRows | Human cCRE → mouse ortholog |
| `CLOSEST_QUERY` | useGeneRows | Closest gene (Distance method) |
| `LINKED_GENES_QUERY` | useGeneRows | Experimental links (Hi-C, ChIA-PET, CRISPRi, eQTLs) |
| `COMPUTATIONAL_LNKED_GENES_QUERY` | useGeneRows | Computational links (ABC, rE2G, …) |
| `GENE_ORTHO_QUERY` | useGeneRows | Genes with a mouse ortholog |
| `SPECIFICITY_QUERY` | useGeneRows | Expression specificity scores |
| `GENE_EXP_QUERY` | useGeneRows | Gene expression (TPM), max or average |
| `LINKED_GENES_CELL_TYPES_QUERY`, `COMPUTATIONAL_CELL_TYPES_QUERY` | LinkageBiosampleModal | Biosamples available for a linking method |

`BIG_REQUEST_QUERY`, `MOTIF_QUERY` and `TOMTOM_MATCH_QUERY` are defined but not currently used.

## Query order inside the hooks

Element and gene data depend on the cCRE intersect, so they wait for it:

```
regions ─┬─ BED_INTERSECT ─┬─ (ORTHOLOG) → MAX_Z_SCORES + BIOSAMPLE_Z_SCORES        elements
         │                 └─ CLOSEST | LINKED | COMPUTATIONAL → (GENE_ORTHO)
         │                                → SPECIFICITY + GENE_EXP                   genes
         └─ ALLELE + MOTIF_RANKING                                                   sequence
```

Each hook uses Apollo's `skip` option to hold back a query until its inputs are ready, or when the category or option is turned off.

## Errors

Each category hook returns `error`, which the detail table shows. On the results page any error in a category gives it no rows. Compass passes `keepPartialSequence`, so if one of the two sequence queries fails it still uses the other.

## Generated types

Types for every query live in [src/graphql/__generated__/](../src/graphql/__generated__/), generated by GraphQL Codegen ([codegen.ts](../codegen.ts)) from the live API schema.

After adding or changing a query:

```bash
yarn gen-types          # needs SCREEN_API_KEY in your environment
```

Queries must be wrapped in the generated `gql()` function (imported from `src/graphql/__generated__/gql`) for codegen to find them and for `useQuery` to infer the result type. Don't edit generated files by hand.
